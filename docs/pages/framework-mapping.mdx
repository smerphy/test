# Framework mapping reference

Praetor ships starter bundles for three major AI governance frameworks.
Each policy in a bundle is tagged via `metadata` with the control(s) it
satisfies, so compliance reports map policy decisions back to framework
controls automatically.

## Agent abuse patterns (hardening bundle)

File: `engine/praetor_engine/bundles/agent_abuse_patterns.praetor`

A framework-independent hardening bundle. Each rule is cross-tagged
to the framework controls it satisfies, so compliance reports surface
it regardless of which framework you're evaluating against.

| Category | Rules |
| --- | --- |
| Credential exfil | private key material; AWS / GitHub / Slack / OpenAI / Anthropic / Stripe / Google / HuggingFace / npm tokens; JWT |
| Credential URLs | redact `?api_key=` / `?password=` / etc.; strip embedded basic-auth |
| SSRF / private nets | cloud metadata endpoints, RFC 1918, localhost, link-local, non-http schemes |
| PII egress | SSN denial, credit-card PAN redaction |
| Prod infra mutation | IAM policy/role mutation, destructive DB on prod, `DELETE` without `WHERE` |
| Shell injection / RCE | reverse-shell signatures (`bash -i`, `/dev/tcp/`, `nc -e`, `socat EXEC:`); `curl … \| sh` |
| Path traversal | `../` sequences; reads of `/etc/passwd`, `/etc/shadow`, `~/.ssh`, `/proc/*/environ`, docker.sock |
| Exfil destinations | Discord/Slack/Telegram webhooks; pastebin / file-share services; `.onion` |
| Container / K8s | `kubectl delete/exec/drain`, `helm uninstall`; `docker run --privileged` / `--pid=host` / `-v /:/host` |
| Privilege escalation | `chmod +s`, `usermod -aG sudo`, sudoers edits, `gpasswd -a`, sudo tool names |
| Crypto wallets | BTC (legacy + bech32) and ETH addresses → require approval |
| Audit tampering | CloudTrail / S3-logging tampering, log-group deletion, Praetor self-tampering |

Load it alongside a framework bundle:

```python
from praetor_engine.bundles import load_bundle

policies = load_bundle("nist_ai_rmf") + load_bundle("agent_abuse_patterns")
```

## Prompt injection & jailbreak detection

File: `engine/praetor_engine/bundles/prompt_injection.praetor`

Scans the common text-bearing tool-argument fields (`prompt`, `message`,
`content`, `text`, `input`, `body`, `query`) for prompt-injection and
jailbreak patterns. Clear manipulation attempts are denied; ambiguous
signals require human approval to bound false positives. Cross-tagged to
OWASP LLM01/LLM02/LLM06.

| Effect | Detects |
| --- | --- |
| `deny` | ignore/override prior instructions; disable/bypass guidelines or safety; jailbreak personas (DAN/STAN/AIM, developer/god mode); roleplay-to-escape; warning/refusal suppression; chat/instruction control tokens (`<\|im_start\|>`, `[INST]`, `<<SYS>>`); "new instructions:" preambles; tool-redefinition (confused deputy); conversation/system-prompt exfil; invisible Unicode tag characters |
| `require_approval` | system-prompt / instruction extraction; indirect-injection markers in content; encoded/obfuscated payloads and long base64 blobs; markdown-image data-exfil channels; zero-width-character smuggling; test/fiction framing used to justify ignoring rules; prompts asking to reveal secrets |

Patterns are written to be linear-time (bounded gaps and character
classes, no nested unbounded quantifiers), so the bundle is not itself a
ReDoS vector.

```python
policies = (
    load_bundle("nist_ai_rmf")
    + load_bundle("agent_abuse_patterns")
    + load_bundle("prompt_injection")
)
```

Red-team test coverage lives in `engine/tests/test_red_team.py` — one
synthetic `PolicyInput` per rule, asserting the evaluator returns the
expected decision.

## Extending

Add your own policies and tag them with the same `metadata` keys
(`nist_ai_rmf`, `iso_42001`, `eu_ai_act`). The control plane's report
renderer treats unknown keys as opaque pass-through metadata, so you
can also add custom framework keys (e.g. `acme_internal`) and they'll
surface unchanged.
