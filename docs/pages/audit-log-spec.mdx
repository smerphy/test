# Audit log spec

The Praetor audit log is **append-only, fsync-on-record, Merkle-chained
JSONL**. The local file is the source of truth; shipping to a control
plane is a separate, at-least-once concern.

## Event shape

One JSON object per line. Fields:

| Field | Type | Notes |
| --- | --- | --- |
| `seq` | int | Strictly increasing within a single log file |
| `timestamp` | RFC 3339 UTC | Decision time, not record time |
| `agent_id` | string | From `PolicyInput.agent.id` |
| `session_id` | string | From `PolicyInput.session.id` |
| `tool_name` | string | |
| `tool_use_id` | string \| null | Provider-specific (Anthropic block id, OpenAI tool_call id) |
| `tool_arguments` | object | The exact arguments the model proposed |
| `decision` | enum | `allow` / `deny` / `transform` / `require_approval` |
| `reason` | string | Verbatim from the matched policy |
| `matched_policy_id` | string \| null | `null` only for default-deny |
| `suggested_transform` | object \| null | Set iff `decision == "transform"` |
| `context` | object | Verbatim from `PolicyInput.context` |
| `evaluator_version` | string | Engine semver |
| `prev_hash` | hex SHA-256 | `"0" * 64` for the first event in the chain |
| `hash` | hex SHA-256 | Of the canonicalized event minus this field |

## Canonical hashing

To recompute an event's `hash`:

1. Take the event as a JSON object **without** the `hash` field.
2. Serialize with `sort_keys=True, separators=(",", ":")`, UTF-8.
3. SHA-256 the resulting bytes; hex-encode.

The next event's `prev_hash` must equal this hash. Verifying the whole
chain is `praetor.verify_chain(path)`.

## Shipping (control plane)

The `RemoteShipper` thread tails the local JSONL and POSTs each event
to the control plane's `/audit/events` endpoint. An `.offset` sidecar
tracks the last successfully-acked `seq`; the shipper advances the
offset **only** after a 2xx response. Network failures back off
exponentially up to `max_backoff_seconds` (default 30s) and never drop
events — the local file is durable.

The control plane re-verifies each event's hash and per-session chain
on ingest; broken links and tampered bodies are rejected per-row, never
silently accepted.

## What this guarantees

- An attacker who modifies any past event breaks verification of every
  event that follows.
- An attacker who deletes a tail of events leaves the local `seq` gap
  visible to the next ship pass.
- Network partitions delay but do not destroy delivery; the chain
  resumes on reconnect.

## What this does not guarantee

- That events were generated by an honest SDK. (For that you need
  signed batches; on the roadmap.)
- That the local disk is not lost. (Mirror to S3 via a second sink.)
